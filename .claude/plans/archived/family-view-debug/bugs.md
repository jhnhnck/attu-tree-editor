# bugs - family-view debug overlay & diagnostics

scratchpad for bugs surfaced *during* this plan's work. anything that turns out to be a pre-existing bug in `notes/bugs.md` territory gets migrated there at `pre-merge` time.

format: one bullet per bug. severity tag `[blocker | important | nit]` up front. phase of discovery in parens.

## open

- [nit] (phase 0, pre-existing) 6 visual-regression e2e goldens fail on trunk: `visual-add-relative`, `visual-akarians-family-view`, `visual-dense-tree`, `visual-multi-union`, `visual-path-highlight`, `visual-secondary-union`. Confirmed by re-running the same tests on the main repo. Trace: commit `2a394ee fix(tree): bump family-view edge stroke widths` shifted edge stroke widths without refreshing snapshots. Not caused by this plan. Should be regenerated in a separate housekeeping commit (`pnpm exec playwright test --update-snapshots`).
- [nit] (phase 0, environment) `notes/examples/` is gitignored, but several unit tests + e2es symlink into it for fixtures (`apps/web/tests/fixtures/Akarians.ged`, `familyecho-sample.html`, etc.). A fresh worktree has none of these resolved. Worktree-setup workaround: copy or symlink the parent's `notes/examples/` and the top-level `My-Family-24-May-2026-103040590.html` into the worktree before running tests. Bigger fix would be to either commit the fixtures or document the setup step in `notes/agents.md`.
- [nit] (phase 1) off-subset side panel caps each reason at 20 names + "+N more". no drill-down or scroll-into-list yet. acceptable for the diagnostic-overlay use case, revisit if a real tree pushes any single reason past 50.
- [nit] (phase 1) the secondary-union-state pill is svg text just below each card; on dense rows it may visually overlap the next rank's connectors when both the pill and the connector are visible. toggle-gated so no production impact; candidate for a stacking strategy if the toggle ever becomes default-on.
- [nit] (phase 1) `subset.ts:classifyRejections`'s rank-cutoff fallback has an O(P²) inner loop scanning every visible person for "is this a parent of someone visible". fine for diagnostic-overlay tree sizes, but if a follow-up phase needs `rationale` on the hot path, invert the walk into a per-person parent set built during the initial BFS.
- [nit] (phase 2) `showCardCollisions` has no positive-case e2e because none of the existing fixtures reliably overlap cards. the negative-case (clean fixture, zero collisions) is covered; consider minting a collision fixture only if a real bug is observed.
- [nit] (phase 3) the watchdog red-badge (`showPendingRecenter` + watchdog-fires) has no positive-case e2e — every UI path that changes selection AND requests a recenter currently also fires `onrecenter`, so the missed-recenter case isn't reproducible without injecting a bug. the happy-path e2e exercises the timer + state via `data-triggered`. revisit when a real palette-jump silent-no-op reproduction surfaces.
- [nit] (phase 3) `recordFocusEvent`'s "match-by-personId" linear scan could mis-attribute a `didTriggerCenterOn` flip if two recenters for the same person interleave before either records. family-view's `recenterOn` is synchronous so the actual window is microseconds; harmless today. consider keying by `(personId, seq)` if a future async recenter path lands.
- [nit] (phase 3) the phase-3 viewport rect recomputes on every pan / wheel frame (4 divisions). cheap, but a candidate for a `requestIdleCallback`-style throttle if a future profile shows overlay work on the hot path.
- [nit] (phase 4) the breakdown panel's `raw` cell renders the float via `Number.prototype.toString()`. on hand-built fixtures the value is clean (`0.0625`); on a multi-path real-world pedigree it may show accumulation drift (`0.06250000000000001`). the `sum-of-rows` cell makes this directly observable, so the diagnostic still works; cosmetic only.
- [nit] (phase 4) `_coiWarnedFor` is per-component-instance; rapid mount/unmount cycles (e.g. dev hot-reload, engine swap) re-emit the console.warn. acceptable for a diagnostic warning; revisit only if a user reports console spam.
- [nit] (phase 4) `getCoiCacheStats()` returns module-cumulative counters; not reset across tree swaps. a `__treeDebug.coi.reset()` affordance would make per-tree memoisation effectiveness easier to read. defer until a real diagnostic case appears.
- [nit] (phase 5) the five fixed-position debug panels (off-subset, focus-log, off-subset-warning, recenter-missed badge, coi-breakdown, layout-metrics) now each carry a collapsible header so the user can stash any body, but they still own their own fixed coordinates and can overlap at narrow viewports. the long-term fix is a single draggable / docked debug container with tabs. routed: take on only if a user reports the crowding is actually painful.
- [nit] (phase 5) `showLayoutMetrics` reports `duration` for the *last* layout pass only; an idle canvas shows whatever the last value was, not a rolling average. a small histogram (or P95 / max over a sliding window) would be more useful for spotting periodic re-layout spikes. defer until a real perf bug surfaces.
- [nit] (phase 5) the `showLastEditHalo` ring is re-keyed on `lastEditPos.id` so its 1s css fade only retriggers when the *id* changes. two consecutive edits to the same person reuse the same dom node and the animation does not replay. parity with the layered overlay's `last-edit-halo` (same re-keyed-by-id pattern); a small `editSeq` bump would unblock it but no caller has asked for it yet.
- [nit] (phase 5) `showLastEditHalo` has no positive-case e2e (toggle on → edit a card → halo appears). reproducing requires double-clicking through to the inspector, which the bottom-left debug-panel chrome intercepts at narrow viewports — the same friction the phase-3 retro flagged. the underlying `debugLastEditedId` is exercised by `redraw-on-edit.spec.ts` already; the family-view overlay just re-renders the halo from the same prop. acceptable.
- [nit] (phase 5) yellow `showLastEditHalo` stroke (`hsl(50 95% 55%)`) achieves ~2:1 contrast against the light-theme canvas (vs ~3:1+ for the other phase-5 strokes). matches the layered overlay's `#fde047` parity, but worth flagging if a user complains the halo is hard to spot in the light theme.
- [nit] (phase 5, e2e-author note) future overlay layers that emit a `data-person-id` data-attr should add a more specific class or testid so e2es using `[data-person-id]` to wait for the canvas don't grab the overlay rect after a toggle. fixed in phase 5's tests by switching to `button[data-person-id]`, but the trap is generic. document in `notes/agents.md` next time the section gets touched.

## closed

- [phase 1 → phase 2] e2e for `showOffSubsetPeople` asserts `>= 0` not `>= 1 with a secondary-union-not-expanded entry`. **closed** by phase 2's `multi-union-3.ged` fixture + the extended `family-view-debug.spec.ts` test "the multi-union-3 fixture surfaces a secondary-union-not-expanded entry" (commit `472549c`).
- [phase 2 → phase 5] `showRankGutterLabels`'s `x="2"` hard-coded screen-px position. **closed** in phase 5: x is now derived from `cardsBBox.x - 0.4` in unit space with `text-anchor="end"` so the gutter parks against the leftmost laid-out card. pan/zoom safe; commit `0c31c37`.
- [phase 2 → phase 5, won't-fix] `showMultiUnionManifold` + `showCoupleCentroidDelta` two-toggle split. **closed** as won't-fix: the n>2 manifold geometry and the 2-partner Δ-line answer different questions (bus / child-anchor markers vs bond-midpoint-vs-centroid). merging them into a single `showAnchorGeometry` toggle was investigated and rejected during phase 5 polish — keeping the two distinct so the colour palette and labels stay unambiguous. reasoning recorded in `log.md` § phase 5 retro.
- [phase 3 → phase 5] four fixed-position debug overlays crowd narrow viewports. **partially closed** in phase 5: every fixed-position panel (off-subset, focus-log, coi-breakdown, layout-metrics) now carries a shared collapsible-header treatment with `data-collapsed` mirroring the body's mounted state. unified-dock follow-up routed as a new nit (no separate action required for this plan).
- [phase 4 → phase 5] breakdown panel is the fifth fixed-position panel. **closed** as folded into the phase-3 panel-crowding follow-up — same collapsible-header treatment now applies to the breakdown panel.
- [phase 4 → phase 5, won't-fix] `__treeDebug.coi` omitted when no consanguinity. **closed** as won't-fix: matches the runtime contract that `EMPTY` results return early; documented in the inline comment alongside the `coi` snapshot construction. devtools readers' `coi != null` guard is the contract.
